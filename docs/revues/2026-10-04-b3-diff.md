## Lecture de B3 à la jauge (sonde G, avant les défauts)

Série `generate --seed perf --devices 500 --runs 2`, scénario = les 14 sortes, B1 sur chaque run : 1 310 nœuds,
20 983 interfaces, 2 086 liens par snapshot (23 Mo chacun). Le diff lit l'oracle sans bruit : 4 nœuds ajoutés, 4 retirés,
6 changés ; 88 / 101 / 24 interfaces ; 7 / 7 / 14 liens ; 32 contrôles apparus, 12 résolus, 1 942 persistants ;
3 couvertures ; 1 `rebooted`, 8 `flapped` ; 5 291 différences volatiles ignorées ; 310 Ko en forme canonique. Sur la
fixture, chaque sorte de mutation se lit comme `docs/07` §6 l'annonce (`tests/diff/test_synth.py`, une sorte par run).

## Critique

Aucun. Les deux garanties structurantes tiennent : **mêmes snapshots ⇒ mêmes octets** (par construction et par le test
entre processus), et **aucun chemin trouvé où B3 produirait un document que le contrat refuse** (un `FieldChange` n'est
émis que si `b != a`, les `fields` sont triés par `path` unique, chaque `changed` par une référence unique, `added` /
`removed` par la clé de sa section, les événements par (sorte, référence) ; relecture de `fields.py`, `sections.py`,
`events.py`). La page ne régresse pas en sécurité : aucun `innerHTML`, aucun style en ligne ajouté (`grep` sur les
sources), CSP inchangée, test « aucune URL » étendu à la page avec diff, données du diff dans le même bloc JSON échappé.

## Haut

**H1 — Les interfaces retirées entrent dans `ifaceByKey` / `ifacesByNode`, et tout ce qui les lit présente les faits de
la run d'avant comme ceux de la run courante.** `model.js:93-106` (`addGhosts`) range chaque `interfaces.removed` dans
les deux index sans que rien, en aval, ne distingue un fantôme : `tip.js:23-27` (`endFacts`, la bulle d'un câble),
`inspect.js:55-56` (`portCard`, la carte d'un bout de câble), `inspect.js:143-158` (`interfaceTable`, la fiche d'un
équipement et son compte « ports physiques up sans câble »), `inspect.js:186` (« Interfaces : N »). Le cas n'est pas
exotique : c'est **tout device injoignable** (`docs/07` Q3 : ses interfaces disparaissent du snapshot, ses câbles
documentés depuis l'autre bout restent). Sonde E, page `diff-unreachable.html` (`fw-edge-01` injoignable à la run 2) :
```
E5 : interfaces de fw-edge-01 dans cette run : 0 | ifaceByKey(fw-edge-01, x1) → { ghost: true, oper_status: 'up', speed_mbps: 10000 }
E6 : bulle du câble vivant fw-edge-01 · x1 ↔ sw-core-01 · Ethernet1/3
     documenté seul · Description · unknown        ← l'oper du câble, lu dans le snapshot : unknown
     changé : aggregate_a, evidence, oper, speed_mbps
     vitesse | 10 Gb/s | 10 Gb/s   duplex | full | full   état | up | up   ← le bout fw-edge-01 : la run d'avant
E7 : fiche fw-edge-01 : collecte : unreachable | Interfaces : 5 | ports physiques up sans câble (1) | occurrences de « retiré » : 0
     ligne : ha1 physical up —      ligne : x1 physical up sw-core-01 · Ethernet1/3 C2|sw-core-01|Ethernet1/3|
```
Avant la brique, la même bulle disait « fw-edge-01 · x1 : absent de interfaces[] » et la fiche « aucune interface
collectée » : c'est une **régression** sur la règle « ce que la page dit est exactement ce que la donnée dit » (`tip.js`
en-tête : « jamais une valeur inventée »). Un lecteur voit un port `up` à 10 Gb/s sur un device que la run n'a pas joint,
dans la même bulle qu'un câble `unknown`, et un compte de « ports up sans câble » fabriqué sur une run passée. Le cas
`device_removed` (nœud survivant en stub) et le cas d'une interface retirée seule donnent le même effet. La page de test
(`test_render.py:57`, `_diff_pair`) ne retire **aucune** interface (`interfaces: 0 ajoutée, 0 retirée, 3 changées`), donc
rien ne couvre ce chemin ; `CLAUDE.md:634` affirme pourtant « interfaces retirés […] jamais comptés ».
**Correction.** Ne pas indexer les interfaces fantômes dans `ifaceByKey` / `ifacesByNode` (un index à part,
`ghostIfaceByKey`, lu seulement par la fiche d'un **nœud fantôme** et par l'onglet Diff) ; `endFacts` et `portCard`
reviennent à « absent de interfaces[] » pour un bout non collecté ; la fiche d'un nœud vivant liste ses interfaces de la
run, et peut ajouter une section « Interfaces retirées depuis la run d'avant : N » marquée `retiré`, sans entrer dans le
compte ni dans le filtre « up sans câble ». Test Node sur une page où `interfaces.removed` n'est pas vide (un device
injoignable suffit) : la bulle dit « absent », la fiche dit « Interfaces : 0 » et « collecte : unreachable ».

## Moyen

**M1 — L'identité de B3 est sensible à la casse ; celle du snapshot ne l'est pas, et le contrat Diff promet le
contraire.** `backend/diff/sections.py:83` apparie les nœuds sur `hostname` exact (de même `interface_key`, `link_key`,
`:95`, `:107`) alors que `snapshot/integrity.py:73-82` définit l'unicité d'un nœud **sans la casse** et que le contrat
impose au stub un nom en `casefold`. `contracts/diff/sections.py:53` (repris dans `CONTRAT.md:1549`) écrit « un stub
devenu device est un nœud changé » : vrai seulement si le device s'écrit en minuscules. Sonde A (fixture, le voisin
annoncé `SW-Core-02` inconnu de `devices` à la run 1, présent à la run 2) :
```
A1 : stub `sw-core-02` → device `SW-Core-02`   nodes added [device SW-Core-02, stub srv-hyp-07] removed [stub sw-core-02] changed []
     links added 4 removed 3 changed 0 · interfaces added 6
A1 bis, tout en minuscules                      nodes changed [sw-core-02] · links added 1 removed 0 changed 3
A2 : même device, `sw-core-02` puis `SW-Core-02` : nodes added 1 removed 1 · interfaces added 6 removed 6 · links added 4 removed 4
```
Le diff n'est pas faux (les octets diffèrent), mais il contredit la règle écrite, et sur une infrastructure réelle où les
hostnames Cisco portent des majuscules, **chaque** entrée d'un device dans `devices` se lira « retiré + ajouté » avec tous
ses câbles, au lieu de « changé ». Le générateur n'écrit que des minuscules : aucun test ne voit le cas. **Correction
(à trancher par Orhan, deux lectures).** Soit l'identité replie la casse partout où le snapshot le fait (nœud, bouts
de lien, interface, couverture, membres de cluster : `hostname.casefold()` dans `identity=` ; la référence du `changed`
prend l'écriture d'`after`, les clés de tri restent exactes) et un test fige A1 ; soit l'identité reste l'octet, et la
docstring, `CONTRAT.md` et `docs/07` D1 le disent (« un stub devenu device est un nœud changé **si le nom s'écrit à
l'identique** »). La première lecture suit `docs/05` (la casse n'a jamais fait une identité dans ce projet).

**M2 — Un `rebooted` entraîne un `flapped` sur chaque port up du nœud.** `events.py:33-43` ne regarde que l'âge et
l'état : après un redémarrage, tout port monté au boot a `last_change_age_seconds ≈ uptime − 300 < elapsed`, même
`oper_status` aux deux runs, donc `flapped`. Sonde B1 (générateur, scénario `reboot`, 12 devices) :
```
reboot de dc01-acc-06 : events {'flapped': 7, 'rebooted': 1} · flapped sur le device redémarré 7 = ses 7 ports up · ailleurs 0
```
À la jauge (sonde G) : 1 `rebooted`, 8 `flapped`. Sur un cœur à 48 ports up, l'onglet Événements annoncera « 49 » pour un
seul fait, et un vrai flap ailleurs se noiera. `docs/07:200` dit « événement `rebooted` sur le nœud, rien d'autre que du
volatil » ; `test_synth.py:209` (`test_reboot`) ne vérifie que la liste des `rebooted`, pas l'absence de `flapped`.
Deux lectures possibles : le reboot **explique** les flaps (ne pas les émettre sur un nœud `rebooted`, ou les compter dans
`details.ports_up_since_boot` de l'événement), ou ce sont des faits distincts (alors l'oracle §6 et l'explication de
l'onglet doivent le dire). Recommandation : la première, c'est ce qu'un ingénieur réseau attend d'une timeline ; le test
affirme alors `flapped == []` sur la série `reboot`.

**M3 — Trois refus que le contrat documente ou implique, et n'applique pas.** La partie C (« Règles transverses »,
`docgen_diff.py:16`) annonce des règles « vérifiées à la validation d'un diff » ; sonde C, tout est **accepté** :
(C1) des événements alors que `elapsed_seconds` < 0, ou = 0, alors que `diff.py:69` et `CONTRAT.md:1695` disent
« vide si `elapsed_seconds` ≤ 0 » ; (C2) la même identité dans `added` **et** `changed`, ou `added` et `removed`
(`_canonical_section`, `contracts/diff/sections.py:45-49`, vérifie chaque liste séparément) ; (C8) un `FieldChange` sur
`uptime_seconds`, champ volatil **déclaré** exclu de `changed`. B3 n'émet aucun des trois, mais le principe de la brique
est « le contrat refuse ce que B3 pourrait émettre à tort ». **Correction** : `events_without_elapsed`,
`identity_in_several_parts` (ensembles des clés d'`added`, `removed`, `changed` deux à deux disjoints, par section),
`field_change_volatile` (chemin ∈ volatils de la section) ; catalogue, partie C et tests. Au passage `docs/07:78` nomme
`change_without_fields`, qui n'existe pas : le refus est le `too_short` de `min_length=1` (`changes.py:38`), absent du
catalogue et de la partie C ; le nommer ou corriger `docs/07`.

**M4 — Les fantômes comptent encore à trois endroits de la page, et un câble retiré s'affiche avec un statut.**
`CLAUDE.md:634` : « jamais comptés ». Sonde E1 / E4 sur la page de la paire des tests (un câble et un stub fantômes) :
```
fiche sw-core-02 : câbles vivants 3 + fantômes 1 → la fiche titre « Câbles : 4 »                (inspect.js:179, links.length)
barre d'outils : « voisins inconnus (0) » | état du graphe : « 5 nœuds sur 6 … · 1 voisin inconnu masqué »  (main.js:57 vs :162-164)
en-tête : « 5 nœuds » | état du graphe : « … sur 6 »                                              (main.js:43 vs :162)
onglet Diff, ligne du câble retiré : « retiré · srv-hyp-07 · 3c:ec:… · sw-core-02 · Ethernet1/3 · confirmé »  (tables.js:188)
```
Le titre « Câbles : 4 » contredit la bulle du même équipement (« 3 câbles · 1 câble retiré », `tip.js:82-86`, qui fait
juste) ; le « voisin inconnu masqué » annoncé par l'état du graphe est le stub fantôme que la case « voisins inconnus (0) »
ne compte pas ; et dans l'onglet Diff la colonne « statut » d'un câble **retiré** montre `confirmé`, son statut dans la
run d'avant, sans le dire (`live = model.linkById.get(id)` trouve le fantôme). **Correction** : « Câbles : N » sur les
vivants, « + k retirés » à part ; la case des stubs compte les fantômes de sorte `stub` quand les changements sont montrés
(ou l'état du graphe ne les compte pas dans « masqués ») ; soit l'en-tête soit l'état du graphe, mais le même total ;
dans l'onglet Diff, pas de statut pour une ligne `retiré` (ou « était confirmé »).

**M5 — « Quelques millisecondes » : 3,2 s à la jauge, dont 2,2 s à relire et revalider deux snapshots.** `docs/07:30`,
`backend/README.md:370` et `CLAUDE.md` promettent quelques millisecondes ; `GET /api/diff` (`api.py:293-296`) relit et
**revalide** les deux snapshots archivés (`diffs.py:44-54`, `Snapshot.model_validate`) à chaque appel, puis compare.
Sonde G (500 devices, 23 Mo par snapshot) :
```
GET /api/diff ≈ relire + valider deux snapshots 2.22 s + diff 0.99 s + sérialiser 0.01 s = 3.22 s
```
La timeline de la V1 « est une suite de diffs N-1 → N » (`docs/07` §1) : dix runs, trente secondes. Ce n'est pas un
défaut de B3 (la fonction tient en une seconde sur 21 000 interfaces, linéaire) mais une promesse fausse de trois ordres
de grandeur, et une décision de conception à prendre avant la toile : `GET /api/snapshot` sert l'archive **sans la
revalider** (octets vérifiés à l'écriture), `GET /api/diff` pourrait de même construire les modèles sans la passe
d'intégrité, ou garder en mémoire le dernier snapshot lu par run (l'archive est immuable), ou enfin stocker le diff N-1
à côté du snapshot comme produit dérivé remplaçable (ce que la décision 7 écarte : à réévaluer avec ce chiffre).
**Correction minimale** : remplacer « quelques millisecondes » par la mesure, et un test de coût qui compte plutôt qu'il
ne chronomètre, comme pour B1.

## Bas

**B1 — Ce que le contrat laisse encore passer (sonde C, tout accepté).** `Event.details` est libre (`changes.py:73`) :
un `rebooted` avec `uptime_after ≥ elapsed_seconds`, sans aucun détail, ou avec `elapsed_seconds` différent de celui du
diff (C3) ; un `MlagDomainRef` dont les deux agrégats sont sur le même device (C4, `refs.py:13-27` ; `MlagDomain` le
refuse) ; `RunRef.snapshot_version` de majeure 2 (C5, `summary.py:15`, la partie B la refuse) ; le même contrôle dans
`appeared` et `resolved` (C6 : impossible en multi-ensemble) ; un chemin qui descend dans une liste, `evidence.0.source`
(C9, « une liste se compare en bloc »). Détails typés par sorte d'événement (deux modèles, discriminés par `kind`),
réutiliser le validateur de `MlagDomain`, borner la majeure de `snapshot_version`, intersection vide des identités
`appeared` / `resolved`.

**B2 — Un contrôle dont seule la sévérité change est `persisted`, et rien ne le dit.** D3 identifie par `(code, refs)` ;
`documented_not_observed` admet `info` et `warning` (`codes.py:113-116`). Sonde B2 : `info` à la run 1, `warning` à la
run 2 sur le même câble ⇒ `persisted = 1`, rien dans `appeared` ni `resolved`. Le passage à `warning` (les deux bouts
collectent LLDP et ne se voient plus) est une information de timeline. Soit la sévérité entre dans l'identité (un
`resolved` + un `appeared`, lisible mais bruyant), soit une liste `checks.changed` de `(ref, before, after)` sur la
sévérité et les détails, soit c'est assumé et documenté dans D3.

**B3 — `SnapshotUnavailableError` est une dataclass `frozen=True, slots=True` héritant de `LookupError`**
(`diffs.py:29-41`). Sonde D1 : `exc.add_note("…")` lève `TypeError: super(type, obj): obj is not an instance or subtype
of type` (effet connu de `slots=True`, qui recrée la classe, sur le `__setattr__` gelé) ; `exc.args == ('unknown',
'from')` ; `raise … from` fonctionne (C-level). Aucun appelant n'ajoute de note aujourd'hui, mais toute instrumentation
(pytest, un `add_note` dans un handler) tombera. Une classe d'exception ordinaire avec deux attributs et un `__str__`
suffit.

**B4 — Branchement.** (a) `api.py:296` : une `DiffError` n'est pas traduite ; sonde D2 (snapshot archivé réécrit avec une
autre `source.infrastructure`) ⇒ `500 Internal Server Error` nu, là où `page_from_archive` (`build.py:36-40`) la rend en
problème lisible ; même traduction en 500 neutre dans l'API, ou 409. (b) `build.py:36` : `_diff_data` rend
`dict | PageOutcome`, et chaque appelant teste `isinstance` : lever `DiffError` et la rattraper dans l'appelant.
(c) `build.py:73` puis `:80` : le snapshot `to` est lu deux fois (dict brut pour la page, puis `Snapshot.model_validate`
pour le diff) : valider une fois et `model_dump` pour la page, ou réutiliser le dict. (d) `cli.py:141-143` : avec un seul
fichier **et** `--infrastructure`, le message est « deux fichiers sont attendus » au lieu de « pas de mélange des modes ».

**B5 — `ld diff` compare une run avec elle-même sans un mot.** Sonde F (archive à deux runs) :
```
F1 --from = dernière run, sans --to  → exit 0 | runs : 66e49a2d… → 66e49a2d… · écart 0s
F2 --from = --to                      → exit 0 | runs : 66db3f0e… → 66db3f0e… · écart 0s

```
`resolve_pair` (`diffs.py:57-71`) déduit `--to` = dernière run même quand `--from` la désigne. Pas faux (`diff(A, A)` est
vide par définition), mais un `--from` seul veut presque toujours dire « depuis cette run jusqu'à la dernière » : avertir
(« les deux runs sont la même ») ou refuser en mode archive. `summary_lines` (`diffs.py:92-103`) cite les deux
`collector_run_id` : accepté, `ld runs` les affiche déjà, aucune valeur d'entité.

**B6 — Page, détails de texte.** `dom.js:82-86` : `elapsedText(0)` écrit « 0 min plus tard » (diff d'une run avec
elle-même) ; l'état du graphe dit « (dont 1 équipement et 1 câble retirés) » alors que le fantôme est **masqué** par le
filtre des stubs (sonde E1 : la parenthèse décrit le total, pas l'affiché) ; les tables de l'onglet Diff ont une

est revenu » dans l'explication : c'est la réponse à Q4 de `docs/07`, à faire confirmer plutôt qu'à laisser dans deux
formulations ; `brief(null)` ⇒ « — » : conforme (« pas de valeur », pas une raison).

**B7 — Tests : ce qui manque.** Aucun hostname avec une majuscule dans toute la suite B3 (M1) ; `test_reboot` muet sur

**B8 — Code.** `engine.py:52` : `_summary(sections: dict, …, found, …)` sans types là où tout le reste est annoté ;

## Vérifié et trouvé correct

- **D1 à D3, par lecture et par l'oracle.** Appariement par la clé de R6 (`order.py` partage les clés du snapshot, une
  seule définition) ; `added` / `removed` entité complète ; listes comparées en bloc (`_walk` ne descend que dans les
  `dict`) ; volatils retirés et comptés par chemin exact (`path in volatile`) ; `source` et `report` jamais lus ;
  contrôles en multi-ensemble avec le **dernier** canonique en `resolved` (`olds[common:]`) ; détails qui changent ⇒
  `persisted` (testé) ; couverture sur les devices présents des deux côtés seulement.
- **D0 et D4.** Direction = celle demandée, `elapsed_seconds` signé en entier (jours × 86 400 + secondes, cohérent pour un
  delta négatif), événements seulement si `elapsed > 0` (testé à rebours : miroir exact des sections) ; `"never"` et
  `null` ne disent rien (`isinstance(age, int)`, `uptime_seconds is None`) ; `rebooted` avec `uptime_before: null` quand
  le device était injoignable avant (sonde B3) : un fait, correctement écrit ; `oper_status` différent ⇒ `changed`, pas
  `flapped` (testé sur `cable_down`).
- **Aucune entité en double, aucun ordre instable.** Identités uniques par construction du snapshot ; `match` sur des
  dictionnaires en ordre d'insertion puis `sorted` partout ; `_walk` sur `sorted(set(before) | set(after))` ; test de
  déterminisme en sous-processus, trois graines, deux diffs différents.
- **Contrat.** Aucun défaut sur aucun champ (`test_no_field_of_any_diff_model_has_a_default`, parcours récursif) ;
  ordre canonique refusé sur chaque liste, `fields` compris ; `counts_mismatch`, `elapsed_mismatch`,
  `change_ref_kind_mismatch`, `event_ref_kind_mismatch`, `field_change_equal` levés et catalogués (test de couverture du
